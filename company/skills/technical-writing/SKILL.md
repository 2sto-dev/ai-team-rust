---
name: Technical writing
description: Short, accurate README files and documentation written for the reader's next action.
---

- Start with what the thing is and the one command to try it; details come after.
- Every command shown must match the project's real files (names, paths, options).
- Prefer short sections, lists and code blocks over long paragraphs; no marketing language.
- Document what is not obvious from the code: setup steps, configuration, limits, decisions.
- Keep the language of the existing documentation (Romanian stays Romanian).
- Never document features that do not exist.
